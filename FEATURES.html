Mujic is a lightweight, ad-free, offline-first music player for local audio files. This page explains how its library, playback, playlists, audio effects, lyrics, appearance, storage and optional online services work—without hiding important caveats in a top-level banner.

01 · Getting started

Mujic is a browser application. It does not require an account or a separate music library server.

  1. Open Mujic. Run npm start in the project directory (Python's HTTP server is used) and visit http://localhost:3000, or open the deployed site.
  2. Import audio. Use the app's file-picker/import action or drag supported audio files onto the app where drag-and-drop is supported. Approve the browser file selection yourself.
  3. Let the library scan. Mujic stores the selected audio and track metadata in IndexedDB. Metadata parsing may load an optional parser from a CDN the first time.
  4. Play and organize. Start a track, create playlists, adjust the queue and personalize settings.
Use a local HTTP server or HTTPS for service-worker and install support. Opening index.html using file:// can behave differently and is not the recommended launch method.

Supported audio files

The import logic accepts files reported as audio by the browser and recognizes common extensions including MP3, M4A, AAC, FLAC, WAV, OGG/OGA, Opus, WebM, AIFF/AIF and ALAC. Recognition does not guarantee decoding: actual playback depends on the browser, operating system and codec support.

02 · Music library

The library organizes files that you choose to import. It does not automatically scan every folder on your device.

Import and metadata

  • Select local audio files through the app's import control, or use supported drag-and-drop.
  • Mujic attempts to read available tags such as title, artist, album, duration and embedded artwork. Missing or malformed tags may result in fallback titles or generic artwork.
  • Audio blobs and metadata are stored separately so the player can retrieve the original local audio for playback.
  • Metadata parsing is loaded on demand through the optional vendor loader. If the CDN is unavailable, parsing may fall back or provide less metadata.

Browse and sort

  • Use Library tabs to browse songs, albums, artists and playlists.
  • Library sorting supports order of the Songs tab, recently added, title, artist or album, with ascending/descending direction.
  • The artwork/list-icon setting controls thumbnails in lists. Artwork can be generated as a placeholder when none is available.
  • Home includes playlist and listening-discovery rails such as Top Picks and Continue Listening, based on the library and listening data available to the app.

Duplicate handling and removal

Mujic attempts to detect duplicates using file information and a lightweight content fingerprint. This is a practical check, not a guarantee that every identical file will always be recognized. Removing a track also removes its cached lyrics and artwork when that artwork is no longer shared by another track.

Clearing the library is destructive: it removes stored audio, artwork and metadata. Exported settings or listening statistics are not a backup of your songs.

03 · Playlists and collections

Playlists are saved in the local browser database and are designed to organize tracks already imported into Mujic.

  • Create a playlist from the playlist area or its New Playlist action.
  • Rename or delete a playlist from its available actions.
  • Use the Add Songs picker to select multiple tracks already in the Mujic library. It is not the same as importing new files from your device.
  • Reorder playlist tracks using the available controls or drag interactions where supported.
  • Open a playlist to play it or shuffle its tracks. Queue order and playlist order are separate concepts.
  • Favorite tracks and Favorite Artists can be accessed through the app's relevant collection areas.

Playlist edits persist locally. Clearing browser site data or clearing the Mujic library can remove local content, so do not treat browser storage as your only archival copy of important data.

04 · Player, queue and playback

The player uses the browser's audio engine and retrieves the stored audio blob for the selected track.

Playback controls

  • Play/pause, next, previous, seek, and volume controls operate on the current queue.
  • Shuffle creates a playback order; repeat modes include normal repeat behavior and repeat-one. The displayed queue and playback order are related but not always identical while shuffle is active.
  • Track actions can add a song to Up Next, add it to the queue, add it to a playlist, or mark it as a favorite.
  • The queue supports reordering and removal. The duplicate-queue setting can prevent adding a track that is already queued.
  • When enabled, Resume Playback remembers the last track and playback position. Resume depends on the stored track still being present and the browser being able to load it.
  • Media Session integration can expose track information and playback controls to the operating system or compatible hardware/browser UI.

Queue behavior

Play a track from a context—such as a playlist, album, artist or search result—and Mujic builds a playback context for it. Shuffle can change the order without permanently rewriting the original queue. The queue regression test checks several reorder and duplicate cases, but it is not a full browser test of every possible interaction.

Keep screen awake

The optional wake-lock setting requests that the screen stay awake while the full player is open. This relies on browser support and user/device policy; it is not guaranteed on every platform.

05 · Audio controls and effects

Open the player’s additional options and the relevant Settings groups to adjust playback. Some effects require Web Audio API support.

Equalizer

  • The Equalizer sheet provides presets and band controls. The current implementation includes preset modes and adjustable EQ bands.
  • Audio filtering uses the browser's Web Audio API when available. If the API is unsupported or unavailable, some processing may not work even if the rest of the player does.
  • EQ settings are stored with the rest of your preferences.

Playback and sound options

  • Playback speed: changes the audio playback rate where supported.
  • Sleep timer: can be turned off, set for 5, 15, 30 or 60 minutes, or set to end of song. When it expires, playback is paused.
  • Audio waveform: choose Off, Default, Wavy, Slim or Squiggly for the played section of the seek bar.
  • Visualizer: the player includes a visualizer option; its animation and performance depend on browser support and device capability.
  • Soft track transitions: briefly fades between tracks instead of abruptly switching; it does not overlap the two tracks.
  • Loudness control: uses a lightweight compressor to reduce large volume swings. Choose Soft, Balanced or Strong profile.
  • Skip long silence: detects sustained near-silence and moves ahead. Instantly skip silence uses a shorter threshold and a somewhat larger skip when the feature is enabled.
  • Auto-skip unsupported tracks: moves to the next queued track if the browser cannot decode the current file.
Effects can change perceived sound and may use extra CPU. If playback glitches on a low-end device, disable optional effects and the visualizer first.

06 · Lyrics and synchronization

Lyrics are optional. Mujic tries local sources first and only uses online providers when the app is online and the relevant fallback is enabled.

Lookup order

  1. Embedded lyrics: lyrics already stored in the audio file take priority.
  2. Local cache: previously retrieved lyrics can be reused offline.
  3. LRCLIB: the app attempts a lookup and then a search, checking title and available metadata to reduce mismatches.
  4. Community lyrics endpoint: an optional community-hosted fallback is attempted if enabled and LRCLIB did not match.
  5. LyricsPlus: an optional final fallback for synchronized lyrics, attempted only on the lazy lyrics path rather than during normal app startup.

Plain and synchronized lyrics

  • Plain lyrics display text without time alignment.
  • Synced lyrics use LRC timestamps to follow the current playback position.
  • Available lyric styles include Apple Music, Spotify and Neon Highlight.
  • Text size, vertical position, fine position and timing offset can be adjusted. A negative timing offset makes lines appear sooner; a positive offset makes them appear later.
  • Lyrics retrieved successfully can be cached for later use. A cache cannot guarantee a match for every song.

Community lyrics source

The community lyrics fallback is served through the Mujic Cloudflare Worker, which relays to third-party providers that are not operated or guaranteed by the Mujic repository owner. They can fail, change behavior or return no match. When the Community lyrics server setting is enabled, Mujic sends the track title and artist to that third-party endpoint after LRCLIB misses. Turn it off in Settings → Lyrics Providers to opt out of this fallback.

LyricsPlus source

LyricsPlus is also a third-party/community service accessed through public mirrors. It is optional and can be unavailable. When used, the lookup may send title, artist, album and duration. Disable LyricsPlus fallback in Settings to prevent this lookup.

Lyrics availability, correctness, timing and licensing are not guaranteed. The app does not upload the audio file as part of these lyrics lookups; metadata is sent to the selected provider as described in the privacy section.

08 · Listening history and statistics

  • Mujic records listening activity locally and can show recent play history.
  • Settings includes listening summaries for today, this week, this month and all time, plus most-played information when enough data exists.
  • History is stored in browser storage and is not an online account-wide profile.
  • Removing a song and clearing all library data can affect associated local records, depending on the action.

Statistics are based on activity the app was able to record; they should be treated as helpful summaries rather than a forensic or cloud-synced listening log.

09 · Data, export and storage

What is stored locally?

  • Imported audio blobs and track metadata.
  • Artwork and cached lyrics.
  • Playlists and preferences.
  • Listening history and statistics.
  • Playback state needed for resume behavior.

Export and import

  • Export Settings: downloads a JSON file of supported preferences.
  • Export Listening Stats: downloads a JSON file containing listening history/statistics.
  • Import Data: restores a compatible Mujic settings or listening-statistics JSON export. Imported values are validated where the app defines allowed ranges and options.
Important: JSON exports do not include your music files. To preserve audio, keep your original files in a separate location. Do not assume browser storage will survive clearing site data, browser cleanup, device reset or storage pressure.

Library size and Clear All

The Storage section shows an estimate of the library's stored size. Clear All removes stored audio, artwork and metadata. Read confirmation prompts carefully before proceeding. Browser storage quotas and persistence policies differ by browser and device.

10 · Installation, updates and offline use

Install as an app

On supported browsers, use the Install Mujic option or the browser's install control. Installation prompts are browser-dependent and may not appear on every platform. If no prompt is available, the app can still be used as a website.

Offline behavior

  • The service worker caches the application shell and local scripts/styles for offline startup after they have been cached successfully.
  • Audio imported into IndexedDB can be played without downloading it again, subject to browser storage and codec support.
  • Lyrics from embedded files or a successful local cache can be available offline.
  • Online lyric providers, font downloads and first-time metadata-parser downloads need network access.
  • Offline support is not the same as guaranteeing that every third-party dependency, fresh install or browser feature works without ever going online.

Updates

The app can check for a newer version and show the installed version. The service-worker cache name is versioned so a new build can replace older cached assets. If an update appears stuck, close old app tabs, reopen the site, and use the browser's site data/service-worker controls only if you understand that clearing site data may delete local library data.

Release-bundle note: this supplied archive's manifest references icons/icon-192.png and icons/icon-512.png, but those image files are absent from the archive. Add them to complete the expected branded install assets.

14 · Troubleshooting

A track imports but will not play

  • Check whether the browser supports the file's codec/container.
  • Try another known-good audio file.
  • If Auto-skip unsupported tracks is enabled, the player may move on after a decode failure.
  • Some browser audio features may be restricted until the user interacts with the page.

Track title, artist or cover is missing

  • The file may not contain embedded metadata/artwork.
  • Try importing while online so the optional metadata parser can load.
  • Browser codec and parser support vary by file format.

Lyrics are unavailable or wrong

  • Check the title/artist tags and network connection.
  • Some tracks do not have lyrics at the providers.
  • Optional third-party services may be asleep, rate-limited, unavailable or return no match.
  • Disable community fallbacks in Settings if preferred; embedded and cached lyrics can still be used.

The app does not install or stay offline

  • Use HTTPS or localhost rather than opening the file directly.
  • Open the app online at least once so the service worker can cache its shell.
  • Check browser support for PWA installation and service workers.
  • The supplied archive lacks the icon image files referenced by the manifest; add those for complete install branding.

Library or settings disappeared

Browser site data may have been cleared, storage may have been evicted, or the app may be running under a different origin. Settings/statistics exports do not contain audio. Keep the original audio files separately.

Performance is poor

Disable the visualizer and optional audio effects, close unused tabs, and test a smaller library. Audio processing and artwork rendering use device resources.

Optional online features and external links can still send information to third parties, as described below.
